\section{Teaching Data}

\file{data/wicced_teaching_water_quality.csv} is a small synthetic teaching dataset. It is built to exercise QA/QC, plotting, and baseline modeling. It should not be used for environmental claims.

\file{data/chemical_screening_template.csv} is a small template for documenting candidate chemical screening records. It is not evidence that those compounds occur in a WiCCED sample.

\file{data/wicced_simulated_gcms_hits.csv} is a simulated uafR-compatible GC-MS hit table. It includes freshwater, agricultural drainage, urban stormwater, tidal-transition, marsh-edge, and aquaculture teaching samples. It is designed to demonstrate how uafR-style processing can organize candidate chemical evidence for water-quality research.

The simulated GC-MS pipeline is supported by three additional files in \file{data/}: a query list, a compound reference table, and sample metadata. These files are training scaffolds, not real field measurements.

\section{Machine-Learning Resources}

The \file{ml_resources/} folder contains the beginner ML guide, glossary, workflow checklist, troubleshooting notes, model-card field guide, and advanced ML extension guide. These resources are written for students who have not previously built a machine-learning model, with the advanced guide clearly marked as post-beginner work.

\section{Running the Smoke Test}

From the repository root:

\begin{rcode}
Rscript training_wicced_water_quality/scripts/run_wicced_smoke_tests.R
\end{rcode}

The smoke test writes outputs to a temporary directory and reports the directory path. It checks whether the core scripts can run in sequence without live database access.

\section{Live uafR Queries}

Live \code{categorate()} or \code{pubchemProfile()} calls should be treated as optional enrichment. They require working package dependencies, internet access, respectful throttling, and careful validation. Students should start with one to three compounds and save the result object before scaling.
